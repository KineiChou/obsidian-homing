# Note Organizer

[English](README.md)

Obsidian 桌面插件：为收件箱笔记推荐目录，并在写作时建议内部链接。移动笔记和插入链接都须经你确认。

当前为**0.2.1 开发预览**，尚未发布到社区插件市场。Note Organizer 是工作名称，正式名称、作者署名和许可证待定。需要 **Obsidian 1.11.4+ 桌面版**，不承诺移动端支持。

## 开始使用

按下方命令构建，将 `dist/note-organizer/` 中的 `main.js`、`manifest.json`、`styles.css` 复制到测试知识库的 `.obsidian/plugins/note-organizer/`，再在社区插件设置中启用。

1. 在设置中选择收件箱与分析服务，配置自己的服务凭据，或连接兼容的本地服务。
2. 用固定合成示例测试连接，再启用归档建议。分析已有收件箱笔记前，核对范围与预计请求数。
3. 从状态栏在主区域打开收件箱整理标签页，左侧查看分组笔记，右侧预览 Markdown 正文。确认推荐目录或改选后才移动；成功后自动前进到下一篇待处理笔记并保留撤销入口。当前笔记也可通过编辑器顶部提示条归档。
4. 执行“为当前文字查找链接”命令，或单独开启自动链接建议。勾选要插入的建议，一次确认；编辑器撤销一次恢复整批文字。

归档和链接共享每日请求上限，自动链接最多使用总额度的 30%（向下取整）。批量预估只读取元数据，不含重试。候选分组和重试可能使一篇笔记消耗多次请求。额度按本机统计，不等于服务商的账单限额。

## 服务、网络与隐私

你需要自行提供服务账号或运行本地模型。远程服务可能收费；发送私人笔记前，请了解当前服务商的条款、数据保留和价格。

分析请求仅发给**当前启用的服务**：

| 服务 | 默认请求地址 |
| --- | --- |
| TypeSafe Jev | `https://api.typesafe.ai/v1/systemone` |
| OpenAI 兼容服务 | `https://api.openai.com/v1/chat/completions` |
| Anthropic | `https://api.anthropic.com/v1/messages` |
| Ollama | `http://127.0.0.1:11434/v1/chat/completions` |

兼容服务可配置自定义基础地址。连接本机 Ollama 时，请选择 **Ollama**，填写基础地址和已安装模型 ID，密钥可留空。默认模型为 `qwen3:1.7b`；远程端点仍需要密钥。插件不会安装或启动模型服务。本地端点也会收到下述内容，是否继续转发取决于该服务。插件不会在失败时悄悄换到另一个服务发送笔记。

分析请求可能包含：

- **归档：** 当前笔记标题、标签、去除属性区的正文，以及候选目录路径、手写用途和继承的规则。默认长文策略在本地提取有长度限制的摘录，包含标题大纲、开头和各节首段，不另调用摘要模型。全文模式在预算允许时发送正文，超出预算则拒绝请求。
- **可选目录画像：** 启用后，候选描述还可能包含该目录其他笔记的抽样标题和标签，不发送这些笔记的正文。默认关闭。
- **链接建议：** 提及文字、所在局部句子、源笔记路径，以及候选笔记的路径、标题、别名、标签和描述／摘要元数据。可能包含尚未保存的编辑器文字。链接索引不会发送全库正文或生成 embedding。
- **连接测试：** 固定合成示例，不含知识库文字。

插件不收集遥测。凭据从 Obsidian 的密钥存储读取，设置只保存密钥名称。诊断日志不记录笔记正文或完整请求。最小归档建议、设置和移动历史保存在本地插件数据中；知识库同步工具可能同步这些数据。建议只保存路径、内容指纹及分类元数据，不保存笔记正文。有效建议恢复时不联系服务，已有收件箱库存仍等待用户选择分析。

## 当前边界

单个收件箱、Markdown、桌面版。链接匹配以文件名和别名为起点，不能发现所有语义关联。建议可能有误，服务返回的排序不代表校准后的置信度；请在确认前检查目标。

无法安全保持引用的移动会被拒绝；若文件已经移动但无法核实链接更新，记录转为需核对，不会自动移回。移动撤销仅限当前插件会话；重启恢复将确定结果归档，不确定的移动留待人工查看。

自动化测试覆盖领域逻辑与编辑器、HTTP、UI 替身。已在 Obsidian 1.13.7 合成库验证目录选择、带入出链移动及两条链接更新、移动撤销、顶部提示条操作，以及两条补链由一次原生 Undo 恢复。补链测试使用本地模拟 HTTP 响应，不代表真实模型效果。Jev 对照使用固定合成示例；真实本地 Ollama `qwen3:1.7b` 四次响应结构有效，但有一次误归档，原生连接检查通过。这只验证协议接入，不能保证真实写作场景的推荐质量。其他宿主版本仍未验证。参见 [Ollama 实测](docs/ollama-acceptance.md)。详见[验证范围](docs/validation.md)与[发布要求](docs/releasing.md)。

## 开发

发布工作流使用 Node.js 22.21.1 与 npm 11.6.2。

```sh
npm install --global npm@11.6.2
npm ci --ignore-scripts
npm run check
npm run package
```

`npm run package` 输出 `dist/note-organizer/`，不安装到知识库，也不发布。开发监视使用 `npm run dev`。参见[模块契约](docs/development.md)、[交互设计](docs/interaction-design.md)、[目录分类](docs/folder-classification.md)与[链接建议](docs/link-suggestions.md)。
