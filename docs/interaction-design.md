# 低打扰交互与设置

状态：交互设计方案，尚未完成插件内实现或用户试用。本文约束界面默认行为，技术边界见 [技术设计](technical-design.md)。

## 目标

插件替用户准备选择，在用户愿意整理时提供一次明确确认。日常写作无需观察插件状态，也无需处理完全部建议。没有采取行动是有效选择。

降低决策成本的方式是减少同时出现的选项、重复确认与无依据的推荐；每次移动或插入仍由用户确认。撤销提供后续恢复能力。

## 用户可见的三个入口

| 入口 | 默认行为 | 用户得到什么 |
| --- | --- | --- |
| 状态栏“整理” | 固定、中性，无可用建议时不闪动；有建议时显示小圆点 | 主动打开时查看当前笔记或收件箱 |
| 整理面板 | 初始关闭，新建议不拉起；用户已留开的面板正常保留 | 看一条推荐、确认或改选 |
| Obsidian 原有设置与命令面板 | 主动打开 | 配置、手动分析、暂停与恢复 |

不再为两个功能分别增加常驻图标、悬浮按钮和未读计数。建议数量可在面板或入口的辅助说明中查看，圆点同时提供可访问文字，不能只靠颜色识别。收件箱积压数量不是“必须完成”的提醒。

命令沿用 Obsidian 的命令面板，提供“打开整理建议”“分析当前笔记”“为所选文字推荐链接”“暂停／恢复自动分析”；默认不绑定全局快捷键。[Obsidian 命令面板](https://help.obsidian.md/plugins/command-palette)

## 首次配置：一页，两项输入，一次启用

1. **收件箱**：显示自动发现的 inbox 候选，用户确认一个完整路径。多个匹配时不猜测；不改变 Obsidian 默认新建笔记位置。
2. **Jev 连接**：选择或创建一个密钥引用。提交后用固定示例检查连接。
3. **启用归档建议**：按钮附近简要说明待归档笔记与候选目录信息会发送到 TypeSafe，点击后启用本机对新进入笔记的自动分析。

其余目录自动发现，范围显示简短摘要与“调整范围”。首次不要求逐个目录写用途，不强迫选择算法、模型版本、置信度或索引方案。

inbox 已有笔记不会随着启用自动上传。在用户首次主动进入收件箱面板时显示一个“分析已有笔记”入口，未选择也不重复提醒。

链接功能默认提供手动命令；用户开启“写作时准备链接建议”后才自动分析编辑停顿。开关旁始终说明默认作用于当前知识库中正在编辑的笔记，包含未保存的局部文字，遵守独立排除范围。无需每篇重新确认发送范围，但扩大范围后须显示新增范围。

## 写作时的体验

自动分析与主动提示分开：开启自动准备后，候选在后台产生，正文、光标和编辑布局保持稳定。插件不在正文增加下划线、幽灵文本、逐词气泡、错误样式或强制提示音。

进入输入法组词、继续输入或切换文件会使不再有效的建议失效；后台过程不通过转圈、进度条或“正在思考”占据编辑空间。用户主动查找时才在对应按钮位置显示一次加载状态。

用户打开面板后，“当前笔记”展示当前上下文建议，“收件箱”提供集中归档，两者不同时展开为两套任务清单。首次打开优先显示当前笔记已有建议；没有当前建议时进入收件箱。用户手动选择的范围在本次面板会话内保持，不被后台结果切换。

当前笔记模式随用户切换编辑文件更新；点击侧栏和选择弹窗不改变绑定的源编辑会话。正文预览沿用 Obsidian 的自然阅读方式，不增加必须学习的另一种阅读模式。

## 归档：确认一个位置

默认卡片示例：

```text
Transformer 学习笔记.md
建议移到 Resources/机器学习/Transformer 学习笔记.md

[归档]  [更改位置]  [更多]
```

标题可打开原文，完整目标路径在确认前可见，可换行；同名目标不能靠省略父路径来追求简洁。只有文件名不变且组合仍完整明确时，才可将文件名和目录分别排版。

- **归档**就是最终确认，不再打开“是否确定”的第二层弹窗。
- **更改位置**打开完整路径搜索，当前推荐预选；人工选择后刷新预览，仍由归档按钮确认。
- **更多**收纳“不再建议这篇”及可选的目录用途说明入口。
- **关闭或不操作**自然表示稍后处理，不需要逐条拒绝或点击“稍后”。

默认不列出三个候选、不展示百分比分数、不要求用户解释拒绝原因。资料不足或模型放弃时不猜一个目标，也不弹出三选一；这些笔记留在默认折叠的“尚未确定位置”里，用户可以主动选目录。模型分数阈值只能在有样本验证后内部调整，不作为用户自助调参任务。

归档成功在原行显示“已归档 · 撤销”，无需全局成功通知。完成行在本次操作期间原位保留，不让下一条归档按钮立即占据刚点击的位置；连续点击同一按钮只执行一次。撤销入口也可从“最近操作”找到，不用几秒倒计时迫使用户作决定。

首版逐篇确认；批量确认应在单条建议质量与真实收益得到验证后再考虑。不得用“非侵入式”作为未经确认自动移动的理由。

## 补链：确认这一处指向这一篇

```text
“我们用 Transformer 编码音频序列……”
链接到 Resources/机器学习/Transformer.md

[添加链接]  [更换目标]  [更多]
```

每处只展示一个目标，点击目标可查看笔记。当前局部最多三条建议，备选只有用户更换目标时出现；不要求用户在写作过程中逐个审阅所有未链接词。

添加链接后原位显示完成状态，编辑器正常撤销可恢复。已经存在的链接继续由 Obsidian 提供反向链接，不额外写入另一篇笔记，也不重复建设一套反向链接面板。[Backlinks](https://help.obsidian.md/plugins/backlinks)

“更多”中的“本次不再提示”在当前编辑会话保持有效，自动保存、别处输入或候选分数变化不会重新提示。用户撤销刚插入的链接，也视为本次写作不再自动推荐该位置与目标。锚点改成其他内容、用户手动重新查找该区域或开始新的编辑会话后才可重新评估。

暂时没有可靠目标时保持安静。仅在用户主动执行查找后显示“暂未找到合适的链接”，不宣称知识库中不存在目标。

## 设置分层与默认值

| 层级 | 设置 | 建议默认值／行为 |
| --- | --- | --- |
| 首次必要 | 收件箱目录 | 发现候选后由用户选择；包含子目录 |
| 首次必要 | Jev 连接 | 用户提供密钥引用，配置只存名称 |
| 日常常用 | 自动准备归档建议 | 首次完成设置并明确启用后开启；关闭保留手动分析 |
| 日常常用 | 写作时准备链接建议 | 默认关闭，手动查找可用；开启后安静地产生建议 |
| 范围与用量，折叠 | 包含收件箱子目录 | 开启 |
| 范围与用量，折叠 | 可归档目录与排除范围 | 自动发现 inbox 外的目标；附件／模板排除建议可核对，不能把名字猜测当作确定规则 |
| 范围与用量，折叠 | 完全不处理的文件／目录 | 用户按需设置；同时约束来源、候选及发送范围，源命中时不发请求 |
| 范围与用量，折叠 | 链接分析范围 | 开启自动链接功能后，默认当前知识库正在编辑的笔记，遵守排除规则；可缩小到 inbox |
| 范围与用量，折叠 | 目录说明与直接归档 | 说明可空；普通目录允许直接归档，仅容器可关闭；通过目录详情局部编辑 |
| 范围与用量，折叠 | 本插件每日分析请求上限 | 初始建议 100 次；按本机本地日历日计，实际发出请求才计入，手动分析、连接示例与重试均占用 |
| 管理，按需进入 | 最近操作、恢复不再建议的笔记 | 查找撤销记录、恢复明确忽略的归档笔记 |
| 管理，按需进入 | 连接／模型／用量详情 | 普通状态、固定模型版本、请求与 token 记录；不展示正文或密钥 |

请求数上限是一个待试用的保守默认值，不是实际费用或账户级硬上限。一个分类任务可包含多次请求，界面在用量详情中解释计数方式。到达后暂停所有新增分析，用户可在同处调整当日上限；不自动提升额度，也不借手动入口绕过限制。调用计数保存在本机，不通过各设备同步制造虚假的全账户用量。

用量模块沿用技术设计的串行存储边界，通过本机 local storage 保存少量额度记录，不为每次按键或本地候选查询写盘。调度器在发送前保守占用额度；意外退出后不能确认是否发出的占用记为未知，不自动归零。连接测试所用静态文本在启用前说明，失败用量未知时保留未知状态。

不进入普通设置的参数包括：分组大小、每组提名数、候选 K、模型 confidence 阈值、前缀树算法、自动机、缓存大小、窗口字符数、输入防抖毫秒数。用户只需表达处理什么、是否自动准备以及允许多少用量。

## 不打扰的反馈规则

| 事件 | 被动状态 | 用户正在操作时 |
| --- | --- | --- |
| 出现新建议 | 入口中性圆点，不打开面板 | 已打开面板可在空闲时追加，不改变正在操作的行 |
| 暂时网络问题 | 有界重试，不发每篇通知 | 当前行显示暂未完成与重试入口 |
| 凭据失效／达到上限 | 入口显示暂停状态，不累计错误角标 | 显示原因与一个“更新连接”或“查看用量”入口 |
| 内容改变导致旧建议失效 | 安静丢弃 | 当前确认动作立即失效；新目标不能无提示接替旧按钮 |
| 归档成功 | 不弹全局通知 | 原行显示结果与撤销 |
| 同名冲突／移动中断 | 保留笔记和待核对记录 | 就地说明，提供更换位置或核对；不覆盖、不循环弹窗 |
| 用户关闭面板／忽略 | 不追问原因，不催促处理 | 立即尊重选择 |

普通建议不使用系统通知、声音、红色未读数字、连续呼吸动画或自动展开。明确失败仍需在用户点击的操作位置可见，避免“安静”变成无法知道操作是否成功。

## 可访问性与稳定性

所有主要操作使用原生可聚焦控件，完整路径与主要动作无需悬停即可看到。当前面板内可通过正常 Tab 导航到确认按钮；Enter 仅激活明确聚焦的控件，不作为编辑区的默认“接受建议”键，输入法组词期间也不消费 Enter。

后台结果不移动焦点，列表保持本次查看次序，不因模型分数变化重排。自动建议变化不逐条朗读；用户主动操作的结果才通过适度的状态播报反馈。字体、对比度和布局遵循 Obsidian 主题，圆点同时有辅助文本。

## 最小验证

先用几条虚构笔记走通写作、打开建议、归档、撤销、更换目标、忽略与额度暂停，检查所有状态能否不查说明就理解。实现后再在真实 Obsidian 中验证输入法、焦点、分屏与撤销。

关注四项实际结果：是否出现非用户触发的弹窗或焦点切换；是否能只判断一个目标后完成一次确认；忽略或撤销后是否重复提示；与原生人工移动／补链相比，实际用时和改选率是否改善。不以建议数量、点击量或清空列表作为产品成功标准。
