# 双链匹配：本地分层、链接统计先验与 `[[?` 查询

状态：已集成于 0.2.4 开发预览（`src/linking/terms.ts`、`metadata-index.ts`、`link-graph.ts`、`mention-matcher.ts`、`target-search.ts`，宿主 `obsidian/controller.ts`，界面 `ui/link-hints.ts`、`ui/link-query-suggest.ts`）。本文是审查基准：阈值、公式和契约如有改动，须同步修改本文。旧方案比较见 [轻量索引](link-indexing.md)，产品边界见 [双链补齐](link-suggestions.md)。

## 1. 目标与原则

1. **本地优先**：标题／别名／派生词匹配、打分和分层全部在本地完成，不联网、不读取其他笔记正文。
2. **模型只处理不确定的情况**：只有“有歧义”的提及在用户悬停时（或用户开启自动判断后）才请求模型。
3. **中文可用**：用分词结果校验中文词边界，既不像纯子串匹配那样误报，也不像“前后不能是字母”的规则那样对中文完全失效。
4. **写入不变**：所有插入仍经 `LinkService.prepare/confirm`，模型响应不能直接写入；`[[?` 只有在用户选中某一行后才替换文字。

## 2. 词条（索引内容）

每篇允许作为链接目标的笔记产生若干词条，每个词条带一个种类：

| 种类 | 来源 | 权重 `w_kind` |
| --- | --- | --- |
| `title` | 文件名（不含扩展名） | 1.00 |
| `alias` | frontmatter `aliases`（最多 32 个） | 0.95 |
| `inflection` | `title`／`alias` 的英文复数变形 | 0.85 |
| `derived` | 从 `title`／`alias` 拆出的关键词（及其复数变形） | 0.60 |

同一笔记的同一词条只保留最高种类（title > alias > inflection > derived）。

### 2.1 归一化 `normalize`

逐个 UTF-16 单元转换，**不改变长度**，从而保证匹配位置可直接映射回原文：

- `A–Z` → `a–z`；其他单元若 `toLowerCase()` 结果仍为 1 个单元则采用（与 Inline Link Suggestions 一致）。
- 全角 ASCII `U+FF01–U+FF5E` → 对应半角后再小写；全角空格 `U+3000` → 半角空格。
- 不做繁简转换（需要字典，列为已知限制）。

### 2.2 长度与停用词

- 词条去首尾空白后长度 2–64 个 UTF-16 单元。
- 纯拉丁字母／数字词条至少 3 个字符；`derived` 的拉丁词条至少 4 个字符，中文至少 2 个汉字。
- `derived` 词条若等于停用词则丢弃：笔记、学习笔记、读书笔记、总结、小结、入门、简介、概述、介绍、教程、草稿、随笔、日记、周报、月报、会议、记录、索引、目录、notes、note、summary、intro、introduction、overview、tutorial、guide、draft、todo、index、readme、misc。
- 用户在卡片中选择“不再提示这个词”后，词条写入设置 `ignoredLinkTerms`（归一化后比较），任何种类都不再提示。

### 2.3 派生规则 `deriveTerms(term)`

按顺序处理，每一步产出的非空片段都作为候选，最后去重并去掉与原词相同者：

1. 去掉成对包裹：`《》`、`「」`、`『』`、`""`、`“”`。
2. 去掉日期或序号前缀：`2024-01-02 `、`20240102_`、`2024年1月2日 `、`01. `、`3、` 等（先匹配 `^\d{8}(?=[\s_-]|$)[\s_-]*`，再匹配 `^\d{4}[-./年]?\d{1,2}(?:[-./月]\d{1,2}日?)?[\s_-]*`、`^\d{1,3}[.、)）]\s*`）。
3. 反复去掉结尾后缀（可带前置空格、`-`、`_`）：学习笔记、读书笔记、笔记、总结、小结、入门、简介、概述、介绍、教程、notes、note、summary、introduction、intro、overview、tutorial、guide。
4. 提取括号内外：`注意力机制（Attention）` → `注意力机制`、`Attention`；半角括号同理。
5. 按分隔符拆分：` - `、` – `、` — `、`：`、`:`、`|`、`｜`、`/`、`、`、`，`、`,`。

例：`Transformer 学习笔记` → `Transformer`；`2024-03-01 读书笔记：置身事内` → `置身事内`；`注意力机制（Attention）` → `注意力机制`、`Attention`。

### 2.4 英文变形 `inflections(term)`

仅当词条以拉丁字母结尾且长度 ≥ 3：追加 `+s`；以 `s|x|z|ch|sh` 结尾追加 `+es`；以“辅音+y”结尾追加 `ies` 形式。只做复数，不做一般词干化，以免 `organization`／`organ` 这类误合并。

## 3. 本地匹配

索引仍是压缩前缀树（[link-indexing.md](link-indexing.md) 方案 A）。节点记录 `noteId → 种类`；单个词条超过 128 个目标或单次扫描超过 128 次命中时截断（沿用原有上限）。

扫描规则：

1. 在每个字素边界起点，沿树走到最长的**有效**词条。有效需同时满足：
   - 字素边界：起止都在字素边界上；
   - 拉丁边界：首字符前、末字符后不能紧邻拉丁字母／数字／下划线；相邻字符按相同归一化规则检查，全角下划线也构成边界限制；
   - **中日韩分词边界（新增）**：若首字符是汉字／假名／谚文，则起点必须是 `Intl.Segmenter('zh', { granularity: 'word' })` 的分词边界；若末字符是这类字符，终点也必须是分词边界。分词是懒计算的：只对被查询位置所在的“片段”（以空白、标点或符号为界）分词并缓存，片段两端本身视为边界；运行环境不支持分词时跳过此项检查。
   - 字素边界的快速路径：文本不含组合符号、零宽连接符、代理对、变体选择符或 `\r` 时，每个位置都是字素边界，不再逐字切分。
2. 同一起点取最长的有效词条；命中后跳过被覆盖的区间（不重叠）。
3. 排除区域：语法树中的代码、公式、链接、URL、图片、frontmatter、HTML、注释、脚注，以及词法补充检查（`[[…]]`、Markdown 链接、行内代码、`$…$`）——沿用 `EditorSession.allowedRanges`。

实测对照（`深度学习` 不再命中标题 `学习`，`注意力机制的作用` 能命中 `注意力机制`，`Transformers` 命中 `Transformer`）见测试 `link-matching.test.ts`。

## 4. 链接统计先验（C）

`LinkGraph` 只使用 Obsidian `metadataCache` 中已解析的元数据，不读取笔记正文。

- 对每篇源笔记 `s` 的 `links`（不含 embeds），得到 `(anchor, target)`：`anchor = normalize(displayText ?? 链接路径的文件名)`，长度 2–64；`target` 由 `getFirstLinkpathDest` 解析，解析不到则忽略。
- 按源笔记保存贡献，源笔记元数据变化时先撤销旧贡献再加入新贡献；笔记删除或被排除时撤销其作为源的贡献。其他源指向它的计数保留到那些源下次更新；候选只来自现有索引，已删除的笔记不会被查到，只会轻微影响 `related` 的分母。
- 维护 `n(a, c)`（锚文字 `a` 链接到 `c` 的次数）、`N(a) = Σ_c n(a, c)`、出链 `O(x)`、入链 `I(x)`。

对候选集合 `K`（大小 `|K|`）中的每个候选 `c`，源笔记为 `s`：

```
commonness(c) = (n(a,c) + 0.5) / (N(a) + 0.5·|K|)                     # 平滑后的“这段文字通常指谁”
related(c)    = |O(s) ∩ (O(c) ∪ I(c))| / sqrt(|O(s)|·|O(c) ∪ I(c)|)     # 共同引用，空集为 0
              + 0.3·[c ∈ I(s)]，上限 1                                   # c 已经链接到 s
folder(c)     = 1（同父目录） | 0.5（同顶层目录） | 0
lexical(c)    = 句内上下文词元与 c 的标签／标题／路径的重叠数，除以 3 后封顶 1
score(c)      = w_kind·(0.6 + 0.4·commonness) + 0.25·related + 0.10·folder + 0.05·lexical
```

候选按 `score` 降序排列，并以路径字典序作为稳定的次序键；最多保留 8 个。若第 8、9 名分数相同，则无法可靠截断，放弃该提及（沿用原规则）。

已知限制：统计在索引构建时解析链接；目标笔记若在源笔记之后才创建，要等源笔记元数据再次变化时才计入。冷启动的库链接少，先验弱，这时主要依赖种类权重和模型判断。

## 5. 分层

对每个提及（锚文字 `a`、排序后的候选 `c1, c2…`）：

- **丢弃**：候选为空；词条在 `ignoredLinkTerms` 中；所有候选都只由 `derived` 词条命中且候选数 > 3；本会话中该位置已被“忽略”（`EditorSession.suppressed`）；候选全部已被当前笔记链接或是笔记自身。
- `short`：纯拉丁词条 < 4 个字符，或纯中日韩词条 ≤ 2 个字符。
- **确定（confident）**：`kind(c1) ≠ derived`，并满足以下任一条件：
  1. `|K| = 1`，且（非 `short`，或 `n(a, c1) ≥ 1`）；
  2. `|K| > 1`，`N(a) ≥ 3`，且 `commonness(c1) ≥ 0.8`；
  3. `|K| > 1`，`related(c1) ≥ 0.4`，且 `related(c2) = 0`。
- **待判断（uncertain）**：其余情况。

确定的提及显示实线细下划线，点击卡片中的“链接”直接生成计划，不请求模型。待判断的提及显示更淡的虚线。

## 6. 模型判断与缓存

**悬停判断**（设置项 `verifyOnHover`，默认开）：悬停待判断提及时卡片先显示“正在判断…”，随后发一次请求：

- 输入：提及文字、所在句子（向前后各至多 240 个单元，截到 `。！？.!?\n`）、源路径、按排序的至多 8 个候选元数据，另加“无需链接”。与现有补链请求的发送范围相同。
- 调度：`priority: 'manual'`，不受自动请求间隔限制；`linkAllowance: true`，计入“自动补链最多使用每日总额度 30%”的子额度，防止悬停挤占归档额度。同一编辑会话的新悬停请求会取代尚未发送的旧请求。
- 卡片状态：判断中显示“正在判断…”与候选；模型选定时显示目标与“链接”；模型认为无需链接时保留卡片说明，并允许手动选择候选；失败时显示原因与候选，不缓存失败。`verifyOnHover` 关闭时不请求，直接列出候选供选择。
- 结论缓存：键为 `源路径 | normalize(a) | 句子文本 | 提及在句中的偏移 | 候选 id@revision 列表 | linkRevision | modelId`，控制器内 LRU 512 条；错误不缓存，重新打开卡片可重试。提及携带该语义键，悬停和确认前重新计算当前句子与候选，正文改变后不能沿用旧位置的结论。
  - 选中某个候选：该提及按“已确认”显示，目标为模型所选；
  - 选择“无需链接”：该句中的这个提及不再显示，直到句子或候选变化。

**写作时自动判断**（原“写作时准备链接建议”，默认关）：编辑停顿后，只对脏区间所在句子中尚无结论的待判断提及批量请求（`priority: 'link'`、`automatic: true`，受 30% 子额度约束），结果写入同一缓存。

**“为当前文字查找链接”命令**：扫描整篇（至多 200 000 个单元）；确定的提及直接成为建议；待判断的提及按距离光标由近到远取至多 24 个，一次批量判断；结果进入批量确认弹窗。

## 7. 实时显示

- 每次正文变化或视口变化时，只扫描可见区域，不联网。扫描窗口向两端各读取至多 240 个单元作为词边界与句子上下文，只返回完整落在原窗口内的提及，避免把窗口外的单词前缀截掉后误匹配。确认校验使用相同上下文范围。
- 最后一次编辑后的 1.5 秒内，**与光标相交的提及**不加下划线，其余照常显示，避免在正在输入的词下闪动。
- 输入法组词期间不显示任何提示。
- 显示档位 `linkHints` 为“关闭”时不扫描；“行尾标记”时每行最多一个标记，悬停列出该行全部提及。

## 8. `[[?` 查询

输入 `[[?匹配文字|显示文字`（`|` 也可写作全角 `｜`；显示文字可省略）触发本插件的建议框：

- **触发**：光标所在行、光标之前最后一个未闭合的 `[[?`；查询至多 64 个单元。若光标后紧跟 Obsidian 自动补全的 `]]`，替换范围包含它。
- **本地候选**：对每篇允许的笔记的标题、别名和派生词，用 Obsidian `prepareFuzzySearch(匹配文字)` 打分，取最好的一项并归一化到 0–1；`rank = fuzzy + 0.25·related + 0.10·folder + 0.2·[n(匹配文字, c) ≥ 1]`；取前 12 个。
- **模型推荐**：匹配文字 ≥ 2 个字符、候选 ≥ 2 个且 `verifyOnHover` 开启时，停止输入 600 ms 后请求一次（上下文为当前行，查询替换为匹配文字），被选中的候选标为“推荐”并移到首位；不自动插入。查询关闭、清空、切换或设置变化使待发请求失效；返回结果只作用于原查询实例，重新输入相同文字也不能复用旧实例的响应。
- **插入**：用户选中后，将 `[start, end)` 替换为 `fileManager.generateMarkdownLink(目标, 源路径, undefined, 别名)`；别名为显示文字；未填写显示文字、且匹配文字不等于目标标题时，用匹配文字作别名。插入前再次核对源范围、当前行、查询位置和目标的身份／版本／路径；过期时提示重新选择。遵守用户的链接格式设置。放弃时正文保留用户键入的文字，不产生任何自定义语法。
- **与原生 `[[` 建议的优先级**：注册后，如能找到内部数组 `app.workspace.editorSuggest.suggests`，则把本建议移到最前；找不到时仍正常注册（可能被原生建议遮挡）。这是对非公开结构的特性检测，失效不影响其他功能。

## 9. 契约变更

- `linking/types.ts`：`TermKind`；`Match.kinds`；`LinkGraph`；`LocalMention`、`RankedCandidate`、`ScanRequest`；`MetadataIndex.documents()`。
- `jev/types.ts`：`RequestScope.linkAllowance?: boolean`；调度器对 `automatic && priority === 'link'` 或 `linkAllowance` 的请求使用 30% 子额度。
- `settings.ts`：`verifyOnHover`（默认 true，同时控制悬停判断和 `[[?` 推荐）、`ignoredLinkTerms`（默认 []，最多 1000 条、每条至多 64 个字符，设置页可逐条移除）。两者只影响显示与交互，不改变 `linkSettingsKey`，因此不会使已有建议失效。
- `EditorSession`：`allowedRangesIn(from, to, parse?)`（整篇扫描时用 `ensureSyntaxTree` 至多等待 200 ms）、`suppressedAt`、`length`、`head`；`EditorSessions.sessionFor(view)`。
- `VaultAdapter` 构造参数新增可选 `LinkGraph`，在 `metadata()`／`remove()` 中维护统计。
- `OrganizerController`：`scanLinks`、`verifyLink`、`linkProposalFor`、`ignoreLinkTerm`、`searchLinkTargets`、`verifyLinkQuery`、`linkMarkdown`；移除 `linkSuggestions`。`findLinks` 改为整篇扫描（见 §6）；自动模式改为 `preverify`，只把结论写入缓存，不再填充批量确认列表。
- `LinkMention.verdictKey: string` 必填；`verifyLink(sessionId, mention)` 用当前语义键校验提及。`verifyLinkQuery(sourcePath, match, line, candidates, isCurrent)` 要求调用方提供实时查询检查；`linkMarkdown(target: LinkTarget, sourcePath, alias?)` 接收完整目标，不能只传路径。
- `LocalMentionMatcher.inputs()` 保留，改为在 `scan()` 之上构造模型输入，供既有调用与测试使用。

## 10. 性能预算

- 构建：词条数约为原来的 1.5–3 倍（派生词与变形）；仍分批让出主线程。链接统计随元数据构建同步完成。
- 每次扫描：只扫可见区域（单次至多 20 000 个单元）；目标 P95 < 2 ms。
- `[[?` 模糊搜索：每次按键遍历全部文档的词条；目标 < 15 ms。

`node --expose-gc benchmarks/link-scan.mjs`（`npm run benchmark:links`）只导入生产模块，合成 2 万篇中英混合标题笔记、每篇 5 条链接；扫描文本为 5 000 个单元、每次命中 128 处（达到单次上限的高密度情形）。2026-09-25 本机（Node 22.21.1、darwin arm64）一次观测：

| 指标 | 结果 |
| --- | ---: |
| 建索引（含派生词与变形） | 132.6 ms |
| 建链接统计（10 万条链接） | 70.7 ms |
| 堆增量 | 约 78 MiB |
| 扫描中位数／P95 | 1.21 ms／1.77 ms |
| `[[?` 搜索中位数／P95（子串打分近似 Obsidian 模糊搜索） | 8.05 ms／8.82 ms |

懒分词与字素快速路径之前，同一场景的扫描 P95 为 3.05 ms。基准不含 Obsidian 元数据读取、CodeMirror 语法树与真实模糊搜索，不代表整体插件耗时。未实现“超出时截断到最近修改的 5 000 篇”，因为实测远低于预算。

## 11. 隐私与发送范围

- 本地层不发送任何内容。
- 悬停判断和 `[[?` 推荐会发送提及所在句子（或当前行）以及候选笔记的路径、标题、别名、标签和简短描述，与原补链请求相同；只在用户悬停待判断提示、或在 `[[?` 中停止输入时发生，并计入额度。设置和 README 须说明，`verifyOnHover` 可关闭。

## 12. 审查清单

1. 归一化不改变长度；中文、表情符号、组合字符的偏移与原文一致。
2. 中文边界：`深度学习` 不命中 `学习`；`注意力机制的作用` 命中 `注意力机制`；分词器不可用时行为退化但不报错。
3. 派生词：停用词、目标数 > 3、括号拆分、日期前缀各有测试。
4. 统计：源笔记更新／删除后贡献被撤销，没有残留计数；`commonness` 和 `related` 与公式一致。
5. 分层：第 5 节每条规则都有正反例。
6. 模型：确定的提及永不请求；悬停只请求一次并命中缓存；“无需链接”隐藏该提及；错误不缓存。
7. 写入：本地确定、模型确认和 `[[?` 选中三条路径都只插入用户确认的目标，并通过版本校验。
8. `[[?`：替换范围包含自动补全的 `]]`；放弃不改动正文；显示文字作为别名；尊重链接格式设置。
