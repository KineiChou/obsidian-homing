## 3. 已验证的缺陷

以下四项都已用临时 vitest 探针在当前代码上复现（探针未提交）：

| # | 问题 | 复现结果 |
| --- | --- | --- |
| [#1](https://github.com/KineiChou/obsidian-note-organizer/issues/1) | 任意目录或设置变化都会丢弃全部建议，且不会重新排队 | `invalidate()` 后状态变为 `waiting`、proposal 丢失；60 s 内 `propose` 没有再次调用 |
| [#3](https://github.com/KineiChou/obsidian-note-organizer/issues/3) | 每次启动都把成功的移动改成 `review`，且永不裁剪 | 100 条 `done` 在 `recover()` 后全部变为 `review` |
| [#4](https://github.com/KineiChou/obsidian-note-organizer/issues/4) | 自动链接的缓存键包含 `documentRevision` | 同一处提及，只改 revision 就请求两次 |
| [#5](https://github.com/KineiChou/obsidian-note-organizer/issues/5) | 长笔记超出预算 | 20 个目录时：9,000 字通过，10,000 字报 `limit` |

其他优化：[#2](https://github.com/KineiChou/obsidian-note-organizer/issues/2) 建议持久化；[#6](https://github.com/KineiChou/obsidian-note-organizer/issues/6) 引用检查过严；[#7](https://github.com/KineiChou/obsidian-note-organizer/issues/7) 批量分析前先确认。

## 4. UI/UX 重做

问题根源在结构，不只是样式：集中归档（需要看正文）和写作补链（需要贴近光标）被塞进同一个窄侧栏。方案是按场景拆分，并移除侧栏：

1. **收件箱整理视图**（[#8](https://github.com/KineiChou/obsidian-note-organizer/issues/8)）：在主区域以标签页打开，左边是分组列表，右边是正文预览，底部操作栏的主按钮直接写目标路径（“移到 Resources › 机器学习”），支持键盘 J／K／Enter／E／S／Z。
2. **编辑器顶部提示条**（[#9](https://github.com/KineiChou/obsidian-note-organizer/issues/9)）：打开有建议的收件箱笔记时出现，取代侧栏的“当前笔记”标签。
3. **链接批量确认弹窗**（[#10](https://github.com/KineiChou/obsidian-note-organizer/issues/10)）：可多选，一次编辑器事务插入，一次撤销全部恢复。
4. **细节**（[#11](https://github.com/KineiChou/obsidian-note-organizer/issues/11)）：状态栏图标加计数；设置页改用 `setHeading` 分组；“更多”改用 `Menu`。

需要产品负责人确认的两点见 [#17](https://github.com/KineiChou/obsidian-note-organizer/issues/17)：不确定时显示备选目录；归档后自动前进。**#17 未确认前，#8 先按“只显示一个目标、不自动前进”实现，并把这两处做成易于切换的开关。**

## 6. 建议执行顺序

每一步在 `dev` 上新建 `feat/*` 分支，完成后以 `--no-ff` 合回 `dev`，`npm run check` 通过后再合入 `main`。

1. **状态正确性**：#1 → #2 → #3。新 UI 依赖“建议能稳定保留”，必须先做。#2 和 #3 涉及 `storage` schema 与 `filing/types.ts` 契约，要一起设计 schemaVersion 2。
2. **成本**：#4、#7。
3. **UI**：#8 → #9 → #10 → #11。#10 涉及 `LinkService` 契约。
4. **发布能力**：#5、#12、#13。#12 和 #13 都会修改错误和设置契约，建议由同一个 agent 按顺序完成，避免冲突。
5. **收尾**：#6、#16、#18，然后 #15 宿主验收、#14 发布物料。

## 7. 不要做的事

- 不要为了省请求而让模型结果自动移动或插入；所有写入仍须经过用户确认的计划 ID。
- 不要在测试中使用真实知识库；不要记录正文、凭据或完整请求。
- 不要把 jsdom 或替身测试结果写成“真实宿主已验证”。
- 修改 `docs/interaction-design.md` 中的交互规定前，先在 #17 取得确认。
