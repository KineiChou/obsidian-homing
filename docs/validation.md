# 开发预览验证记录

0.2.1 历史验证日期：2026-09-24。环境：macOS arm64、Node.js 22.21.1、Obsidian 1.13.7。自动化测试使用合成内容、内存端口及模拟 HTTP；原生验收使用独立合成 vault。本轮还执行了 38 次固定合成内容的真实 Jev 对照，以及隔离 Ollama 实测；没有把用户知识库用作测试夹具。

## 0.2.5：重新进入时重试无目录建议的笔记（2026-09-25）

基线 `651e349`（0.2.4）只在 `waiting` 时触发打开分析，遗漏 `failed` 和 `unassigned`。新增回归在旧实现中复现三项失败：失败后切回、未选出目录后切回、关闭失败笔记后重新打开。现在切换进入时覆盖这些状态及尚无队列记录的有效笔记；相同活动路径的重复事件不触发额外请求，启动恢复、已有目录建议、进行中任务和忽略状态保持原有边界。

`npm run check` 通过 TypeScript strict、ESLint、284 项测试（26 个文件）及生产构建。切换集成覆盖上述重试、重复事件去重、已有结果复用、忽略笔记、未建队列项及启动恢复；既有正文来源与取消回归继续通过。

Obsidian 1.13.7 独立合成库中，本地模拟服务分别让两篇笔记首次返回无效响应与 `unassigned`。切换回来后，两篇都再次请求并在整理弹窗显示 `Resources/ML`；共四次请求，成功后再次往返没有新增请求。服务与合成库测试插件均在验收后停止。本轮没有调用真实模型或使用用户笔记作为测试内容。

## 0.2.4：切换笔记分类与 OpenRouter（2026-09-25）

基线为 `c80f5cc`（0.2.3）。`npm run check` 通过 TypeScript strict、ESLint、278 项测试（26 个文件）与生产构建。新增切换集成测试使用真实控制器、队列、分类器和胶囊，搭配内存 vault 与模拟 HTTP；同一组测试在基线中 3 项失败、1 项通过，修复后全部通过：

- 模拟宿主已切换文件身份但编辑器仍显示上篇正文，打开分析读取新笔记的已保存内容；手动分析仍读取未保存正文。
- 第一篇请求未完成时切到第二篇，第二篇显示“准备中…”；每篇各发一次请求，重新打开恢复各自建议。
- 等待中的请求被取消、恢复自动分析后，再次打开可以重新分析。
- 胶囊另有回归覆盖切换后迟到的移动与撤销失败，不得覆盖当前笔记的反馈。
- OpenRouter 覆盖默认设置、请求地址／模型／鉴权／动态 JSON Schema、参数支持路由、HTTP 与响应内错误、严格目标校验，以及设置切换清除旧凭据、模型修改持久化。

Obsidian 1.13.7 的独立合成 vault 中，两篇测试笔记经本地模拟 HTTP 分别建议 `Resources/ML` 与 `Projects/Active`。首次等待显示“准备中…”，来回切换保持各自目标；共两次请求，正文均对应请求的笔记，重新打开没有新增请求。设置页实际显示 OpenRouter 选项、默认基础地址、完整模型 ID 与结构化输出说明。模拟服务在验收后停止。

本轮没有调用真实 OpenRouter 服务，也未使用真实笔记测试推荐质量。密钥、模型可用性和实际响应延迟仍需用户配置后通过连接检查及使用验证。

按 [双链匹配设计](link-matching.md) 实现本地分层匹配、链接统计先验、悬停判断和 `[[?` 查询。`npm run check` 通过：223 项测试（24 个文件）、类型检查、ESLint 与构建。新增测试逐条对应设计文档 §12 审查清单：

- `link-controller.test.ts`（真实控制器与 CodeMirror）：元数据构建统计；本地扫描零请求；悬停判断只发一次、只含所在句、计入补链子额度、他处编辑后复用；“无需链接”隐藏；“不再提示”写入设置；本地提及生成正常的确认计划。
- `link-hints.test.ts`：明确／歧义两种下划线；只有光标处的提及在输入时隐藏；明确提及不请求模型；悬停只请求一次；“无需链接”后仍可手动选择；关闭按需判断；命令对两种提及的不同行为；原有弹窗、焦点和光标计时回归。
- `link-query.test.ts`：`[[?` 解析与 `]]` 吞并、别名规则、本地结果即时出现、停顿后一次推荐与重排、只有选中才插入。

只测索引本身，未包含 Obsidian 元数据、编辑器、界面、网络或调度让出时间；并非整体插件内存和启动耗时。生产启动会分批让出主线程。本地匹配模块没有文件 I/O 接口。结果依设备和语料而变，不代表中文召回率或最坏情况保证。先前算法比较保留在独立 benchmark 中，不与本次生产实现测量混淆。

## 历史 Jev 冒烟（2026-09-23）

`node scripts/jev-smoke.mjs` 使用生产 JevClient，从标准输入接收密钥，不落盘；只发送脚本内固定的虚构文本。

| 场景 | 实际选择 | 返回输入 token | 本次延迟 |
| --- | --- | ---: | ---: |
| 英文连接示例 | learning，符合预期 | 318 | 698 ms |
| 中文目录：机器学习／电气 | f1 机器学习，符合预期 | 422 | 707 ms |
| 中文 Transformer 同名消歧 | n1 注意力模型，符合预期 | 415 | 432 ms |

三次均返回 jev-1.13.0，通过生产响应校验，合计 1,155 输入 token。此记录不包含密钥、账户信息或用户笔记，不作为准确率估计。

2026-09-23 使用标题为 `Study notes` 的合成对象序列化笔记复现多目录失败：384 个虚构目录形成 6 组、每组 65 个选项，其中一组概率合计 0.99，旧解析器将 HTTP 200 响应拒绝为无效。修复后再次调用，仍出现 0.99 的分组概率；生产分类器完成 6 组提名和 19 项决选，推荐对象序列化目录，共返回 23,190 输入 token。64 目录的直接分类及另一篇多主题合成笔记也通过响应校验。这验证响应兼容与分组流程，不代表真实语料准确率。

## 剩余验证与限制

1. 最低支持版本 1.11.4 未实机验证；中文 IME、源码／实时预览切换、Obsidian 私有语法、链接 redo、同名与图片附件组合、同步和外部编辑竞争仍需补齐。移动端不在本版支持范围。
2. 真实 OpenAI、Anthropic 服务没有验收。Ollama 已做小模型协议及连接检查，大候选集和长上下文未测。历史与本轮 Jev 固定例子均不构成真实语料准确率估计。
3. UI 和错误支持中英文，分类提示仍使用中文；英文对照和目录画像消融已有固定合成结果，目录画像默认关闭，其在真实笔记中的效果仍未知。
4. 大规模同步事件、完整插件内存峰值与真实语料召回率未测量。元数据匹配不读取全库正文，不提供 embedding 语义检索。词条、候选数量和上下文均有上限，可能减少覆盖。
5. 自动更新内部链接配置缺失或关闭时，移动采用保守检查；文件已移动但后置复核失败时转为需核对，保留当前位置。撤销仅限当前插件会话，跨重启不会自动重放移动。
6. frontmatter 在开头 1,200 UTF-16 单元内未闭合时不提供补链。额度为本机请求计数，预估不含重试，不等于服务商账单；无跨设备锁。
7. GitHub Actions 发布流程尚未远程执行；正式名称、作者署名和许可证按用户决定暂缓。尚未创建 Release 或提交社区市场。
